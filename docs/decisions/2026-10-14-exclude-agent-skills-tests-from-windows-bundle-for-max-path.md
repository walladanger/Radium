# 2026-10-14 — Expand the agent-skills resource glob to exclude tests/ from the Windows bundle

- **Context:** The Windows release bundle listed `resources/agent-skills/**/*` as a single
  Tauri resource glob. That subtree (added by PR #114) contains 38 skills with a `tests/`
  directory and 8 fixture files whose absolute paths reach 250–260+ characters, so NSIS
  aborted at `installer.nsi line 7201` on a Windows `MAX_PATH` (260) overflow. Tauri v2
  resource globs (`glob` 0.3.4) support only `*`, `?`, `[...]`, `[!...]`, and `**` — there is
  no negation, so "include everything except `tests/`" cannot be expressed in the glob itself.
  The `tests/` fixtures are never read at runtime: bundled-skill discovery only reads
  `SKILL.md`.

- **Decision:** Replace the single `resources/agent-skills/**/*` entry in both
  `src-tauri/tauri.conf.json` and `src-tauri/tauri.windows.conf.json` with explicit resource
  entries generated by walking the `agent-skills` tree and omitting any path component named
  `tests`. A checked-in generator (`files/generate-agent-skills-resources.mjs`) emits the
  entries and validates that none contains a `tests` component or exceeds 250 characters, and
  `files/apply-agent-skills-resources.mjs` rewrites the two config files from the emitted JSON.

- **Consequences:** Windows NSIS (and MSI) bundling no longer trips `MAX_PATH`; test fixtures
  stay out of the shipped installer. The trade-off is that the two config files now carry a
  large, generated `resources` array (~786 entries) that must be regenerated whenever
  `agent-skills` gains or loses top-level files or skills; the generator is the source of truth
  for that list. Runtime skill seeding (`copy_tree`) can still copy `tests/` at install time,
  which is a separate, non-blocking size concern.
